# The Tree: theory of operation

Status: sapwood (in service, not yet frozen). Recorded 2026-10-04.
Working name of the framework: undecided. Candidates: Heartwood, Cambium. The name stays open until it has held for a few days, the same way anything in this framework earns its freeze.

## Purpose

AI agents can now do real work on their own. In the first Marker stand, an agent connected through MCP worked the portal correctly. That is impressive. It is also exactly what should worry anyone, because the same capability without receipts is unaccountable.

This framework is built so that agent work is checkable. An agent cannot hand over a conclusion. It can only hand over a trail. Every claim, check and finding is a receipt with an identity on it, and the receipt is the only way anything gets onto the record. When the agent is wrong, you can point at the exact node where it went wrong.

The rule makes no distinction between agents and people. Both file the same receipts and face the same scrutiny.

## Thesis

Trust is accumulated falsifiable claims over time, hashed and timestamped.

A claim is useful only if there is a test that could prove it wrong. A check that cannot fail is decoration. If a tired person can't read it in thirty seconds, it isn't a check.

## Genesis and Heaven: the root of trust

Genesis (genesis-protocol) is the root of trust. It holds the signing identity, and its GPG-signed law tags live on the Heaven remote. The private key is kept out of every repository.

The model is a military or DoD offline root certificate authority. The root does no daily work. It stays disconnected so that a compromise further up the chain can never reach it. It comes out only for a deliberate ceremony, signs the next layer, and goes back. Its strength comes from what it refuses to do.

So nobody builds on Genesis directly. Genesis signs a generation, and that generation does the work, takes the risk and faces the fleet. If a generation goes bad, it is revoked and Genesis signs a new one. The thing allowed to take risks and the thing that must stay trustworthy are never the same thing.

## The lifecycle: a tree

A tree trunk, in cross-section, already has the structure this framework needs.

- Cambium is a thin living layer under the bark. It is the only part of the trunk that grows. Each year it lays down a ring, and that ring hardens into permanent, dated record.
- Sapwood is hardened wood that is still active. It carries water and bears load, but it has not been sealed.
- Heartwood is the center. It has finished growing and become pure structure. The tree stands because the heartwood stopped changing.

Becoming heartwood is promotion, not death. A layer proves itself and then stops changing on purpose, so that the next layer can grow against it.

### States

| State | Meaning | Example |
|---|---|---|
| Seed | A new instance born from heartwood. It carries its lineage, identity and model/provider stamp. It is authorized to grow but not yet alive. | A generation signed by Genesis |
| Cambium | Alive at the edge. Editable, doing the work. | The current Marker stand |
| Sapwood | Committed and in service, on probation. Watched and gathering receipts, still revocable. | A pushed commit not yet tagged |
| Heartwood | Sealed. Signed, frozen, built upon, never edited. The next seed is born from it. | Genesis; an annotated freeze tag |

In-flight is the state between two of these. A transition is not an instant. It has a beginning, a running phase that can last a long time (a pipeline in progress, an epic under way), and an end. In-flight is a real state that can be queried: "what is in flight right now?" is a question the record must answer.

Everything is always either in exactly one resting state or in flight between two.

### Transitions

States are nouns. Transitions are verbs, and every one of them leaves a receipt.

- Seed → Cambium: germinate
- Cambium → Sapwood: commit and put into service
- Sapwood → Heartwood: freeze and sign
- Heartwood → Seed: spawn the next generation

The cycle loops back to seed. It is not a closed loop like the ouroboros, a snake eating its own tail, because it has a root that holds still and a lineage you can trace back to it. It is a tree that drops seeds.

## The receipt

Each act is recorded the way a PowerShell advanced function runs: begin, process, end, with try / catch / finally.

- The ledger write lives in finally. It runs whether the act succeeded, failed or was denied. The act can fail; the record of the attempt cannot.
- The write is atomic and append-only. The hash is computed before the write, so a torn write fails verification instead of passing as truth.
- The entry records what was attempted, by whom, and how it ended.
- The function that writes the receipt is itself signed, so every entry also proves that the recorder had not been swapped out.

## What a record can prove

These are separate guarantees, and each one comes from a different mechanism.

| Guarantee | Question it answers | Mechanism | Status |
|---|---|---|---|
| Order | Did this come before that? | Hash chain | Have |
| Integrity | Was it changed afterwards? | Hash | Have |
| Identity | Who made it? | Signature | Have (signed tags) |
| Time | Did it exist by this date? | External timestamp authority (RFC 3161) | Next |
| Inclusion | Is it in the record, and was nothing silently removed? | Transparency log / inclusion proof | After time |
| Non-equivocation | Did everyone see the same log? | Certificate Transparency-style auditing | Horizon |

A hash chain proves order but not wall-clock time. A chain can be perfectly valid and still carry any dates its author likes. Time needs an outside party with no stake in the claim, a notary. Genesis proves order and identity. The timestamp authority ties the chain to the clock everyone shares.

## The scrutiny dial

Not every act deserves the same ceremony. A convenience store keeps a receipt roll. A bank vault keeps a receipt roll, two signatures, a camera, and a log of who opened the camera. A tenant reading its own graph is the convenience store. Genesis signing a generation is the vault.

Open question: which rule decides how much scrutiny an act gets? Once that rule is written down instead of decided case by case, it becomes policy as code: deny by default, the Axiology layer.

## The two trees

The garden has two trees, and they do different jobs.

- The Tree of Life is continuation: lineage, descent, what persists and propagates. In this framework that is the record (chain, ledger, Genesis to seed to heartwood). It answers "where did this come from?"
- The Tree of Knowledge is discernment, the knowledge of good and evil, which means judgment. In this framework that is tests, policy and deny-by-default, the judgment at every transition. It answers "should this be trusted?"

One tree remembers and the other judges. A trustworthy system needs both. They line up with the split already in the build: the outward half (structure, receipts, lineage) is solid, and the inward half (judgment turning back on itself) is held as unproven. Only the structure of the story is taken here. Its moral of a fall and an exile does not apply, because judgment in this framework is the feature, not the cost.

## Calcified air

Richard Feynman pointed out that a tree is made mostly of air. It pulls carbon out of the atmosphere and uses sunlight to lock it into wood. When the wood burns, the warmth is that stored sunlight coming back out.

The ledger works the same way. Events are formless, like air. Energy (scrutiny, tests, signatures) fixes them into rings that stay. Heartwood is calcified air, and the record is calcified events.

## Heat, pressure and time

Carbon becomes diamond only with all three. Take one away and you get something brittle.

- Time: generations, accumulated stands, the ledger's depth.
- Pressure: constraint. Stop rules, tests that can fail, deny-by-default.
- Heat: the passion brought to the work. Without it, time and pressure only produce compressed carbon, a check that is just decoration.

## Accountability without an overlord

The concern this framework exists to answer is someone using autonomous agents to make themselves an unaccountable authority over other people.

- Heartbeat and revocation. Every generation checks in with its root on a schedule. A generation that goes silent, or whose receipts stop matching its claims, has its signature withdrawn rather than renewed. Trust is withheld, not enforced.
- Quorum. No single key promotes a generation to heartwood or revokes one. A threshold of independent signers is required, as in a root CA key ceremony. That includes the framework's author.
- Independent verifiers. Different AI systems (for example Claude and Grok) cross-check claims against receipts. Their role is checking falsifiable claims, not judging intent or morality. Judgment of purpose stays with accountable humans.
- Known limit. This can stop only a lineage that descends from a root it answers to. It cannot stop someone who copies the ideas and builds a tree without receipts. What it does is make accountable agents verifiable to anyone who asks, and make the absence of receipts obvious.

Rules: keep checks mechanical (does it check in, do its receipts match its claims, did it stay inside policy). Never base them on inferred intent. A system that rules on who is good becomes the surveillance this framework exists to prevent.
